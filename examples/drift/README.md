# Drift walkthrough — freeze, run, accept

A data-free, network-free tour of CAMBER's [drift detectors](../../docs/AHU-DRIFT.md): they compare
a **current** window against a **frozen baseline** one, so the workflow has three verbs, not one.

The site is generated by `make_data.py` from `camber.ahusim` — the same physics generator the drift
family's accuracy harness uses. Three air handlers:

| Equip | What it is | What you should see |
|---|---|---|
| `AHU_1` | healthy baseline month, then a **loading filter** | `fault`, locus `air-path` |
| `AHU_2` | healthy throughout | `ok`, locus `steady` |
| `AHU_3` | only an airflow point mapped | **not evaluated** — never `steady` |

## Run it

```sh
python examples/drift/make_data.py                        # writes trends/
camber drift freeze examples/drift/config.json            # establish the references
camber drift list   examples/drift/config.json            # what is frozen, and on whose say-so
camber drift run    examples/drift/config.json            # score current vs baseline
camber drift report examples/drift/config.json --out examples/drift/drift.html
```

`camber run examples/drift/config.json` does the same scoring and folds the verdicts, caveats and
tables into the ordinary audit report (`audit.html`).

## The three verbs, and why

**`freeze` creates.** A run that fits the baseline from the window it is judging is circular —
whatever the equipment is doing now becomes, by construction, normal. So scoring never writes:
`run` and `report` leave `baselines.json` byte-identical, and `freeze` is the only create path. It
refuses to overwrite an existing reference (run it twice: the second says `froze 0 new baseline(s)`).

**`accept` moves.** When you actually fix something, the reference *should* move — but only on
someone's say-so:

```sh
camber drift accept examples/drift/config.json \
    --equip AHU_1 --by "A. Engineer" --reason "filter replaced"
camber drift list examples/drift/config.json --equip AHU_1
```

`--by` and `--reason` are required (argparse rejects the command without them, and the store rejects
an empty one), `--equip` is explicit — there is no blanket "accept everything" — and the superseded
record is kept in `history`, so what was normal, when, and on whose authority stays answerable.
`--dry-run` shows the moves without writing.

## Two things worth noticing in the output

**Before you freeze, nothing is claimed.** Run `camber drift run` before `freeze` and every detector
declines for want of a reference — so no equipment is reported `ok`. An untested unit is listed as
not evaluated, never as steady. Same for `AHU_3`, whose points never resolve.

**Severities are screening-grade.** Every command prints the two-class threshold note and there is
no flag to hide it: the magnitude floors are characterized for the signal class but not for *your*
machines, and the CUSUM timing parameters are untuned. Read a drift finding as "worth a walkdown".
See [CHILLER-DRIFT.md](../../docs/CHILLER-DRIFT.md#calibrating-the-thresholds) for calibration.

Generated files (`trends/`, `baselines.json`, `audit.html`, `drift.html`) are git-ignored.
